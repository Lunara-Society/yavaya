Roadmap

Foundations first. Then the districts.

Status shows what is built, not what is planned. We do not give dates we cannot keep.

Phase 0 · Foundation

Built

Architecture, database, identity, authentication, permissions, audit and security. Plus the pieces everything else depends on.

  • Identity and YAY ID
  • Token ledger
  • Reputation engine
  • Trust Shield
  • Rate limits
  • DEMO content framework
  • Payment layer

Phase 1 · Core Yavaya

Planned

Before opening: email delivery, photo storage and the moderation workflows.

  • Mercadito
  • Community
  • Animals
  • Impact
  • Tokens
  • Notifications
  • Visible Trust Shield

Phase 2 · Work and movement

Planned

No driver is active before approval. Work uses subscriptions, kept separate from tokens.

  • Work
  • YavayaGo
  • Driver network
  • Restaurants

Phase 3 · Depth

Planned

More intelligence on the same foundation of trust.

  • Advanced reputation
  • Recommendations
  • Automation

Phase 4 · Payment infrastructure

Planned

Until a real payment protection system exists, Yavaya will not say it "protects your transaction".

  • Split payments
  • Automated restaurant payouts
  • Automated driver payouts
Rules for every phase

What does not change

  • Never say something works when it does not.
  • Never fake a successful payment.
  • Never invent users, reviews or statistics.
  • Test, review security and check on a phone before opening.
